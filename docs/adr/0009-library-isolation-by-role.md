# Each Service gets the minimal storage access its Roles need, one tree per Library

The goal is to limit what a fully compromised Service can destroy: SABnzbd must not be able to wipe the TV Library, Sonarr must not be able to delete Movies, and Plex and Emby must not be able to write to any Library. Unix ownership cannot carry this: the media tree is one dataset, an Organizer's import is a rename that keeps the Downloader's UID, and a non-root Organizer cannot `chown` a file to itself. So access is scoped by what each Service mounts, and the shared group plus setgid directories give access within it, with a default ACL that keeps new files group-writable (every Service runs at umask 0022). There are no named-user ACL entries, and each media app Service has its own UID, which grants nothing but records which Service created each file ([0552](../research/0552-unix-identities.md)).

Each Library gets its own tree, `/media/<library>/{library,usenet,torrents,ingest}`, and its one Organizer mounts that whole tree as a single bind mount; `ingest/` is the Library's Ingest Folder, where it has one, and `usenet/` and `torrents/` exist only where the Organizer uses that kind of Downloader. Docker bind mounts are separate mount points, so a rename between two of them fails with `EXDEV`; the Organizer would fall back to copy-then-delete, and hardlinks for seeding would break. Downloaders mount only their download folders. Media Servers mount Libraries read-only, except a recordings Library they organize themselves. Media bind mounts never create their source (`create_host_path: false`): a missing folder fails the Deploy, instead of Docker creating an empty `root:root` folder that a Media Server would read as an emptied Library. A Service holding several Roles gets the union of what those Roles need, and nothing more. Organizers copy rather than hardlink from `torrents/` (Sonarr, Radarr and Shelfmark), so a seeding Downloader keeps no link to a Library file; on ZFS the copy should be a block clone.

Shelfmark is the Requester and Organizer for Audiobooks: it takes over its own finished downloads and places them in the Audiobooks Library, one folder per book. It cannot adopt downloads it did not start, so it is the only Requester for Audiobooks. Books is a two-Service chain: Shelfmark, as Requester, passes the Downloader's finished file into Calibre-Web-Automated's Ingest Folder, and Calibre-Web-Automated, as the Books Organizer, moves it into the Books Library. CWA consumes the Ingest Folder, so Shelfmark never hardlinks into it, and Shelfmark never mounts the Books Library.

Games is the exception to the `/media/<library>` layout: it has its own dataset, `andromeda/games`, so daily Periodic Snapshots can protect the Operator's curation without snapshotting the much higher-churn media dataset (#731). `verified/` holds Verified Sets and is readable only by the Operator; `library/` holds the curated ES-DE tree and `switch/` holds Switch titles. Clients read the playable trees over SMB3, never NFS, through a read-only client login. ownfoil mounts only `switch/`, read-only, as a Media Server. Libraries and Verified Sets belong to the Offline Copy scope (#732), not the nightly Backup.

## Considered Options

- **One `/media` mount for every Organizer** (the TRaSH Guides layout): rejected; it gives every Organizer write access to every Library.
- **Separate bind mounts per folder**: rejected; every import becomes a full copy, and seeding hardlinks break.
- **Separate datasets for every Library**: not needed for isolation; one tree per Library on the existing media dataset gives the same isolation with renames only. Games uses a separate dataset for its different Periodic Snapshot policy.
