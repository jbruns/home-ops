# One Stack per app, each with its own Datastores

The original four Stacks (common, home, media, monitoring) were topical, but network isolation, `depends_on` ordering, deploy blast radius, and backup scope all line up with a single app and its Datastores. We split them into one Compose project per app, each in its own `tn/<stack>/` folder; the topical names survived only as prefixes on volumes created before the split. Datastores are never shared across Stacks: Vaultwarden gets its own MariaDB instead of sharing Nextcloud's. Existing named volumes kept their old names (e.g. `home_vaultwarden_data`) via an explicit `name:`, so the split moved no data. [ADR 0010](0010-volumes-named-for-their-stack.md) supersedes this: volumes are renamed after the Stack that owns them, by a planned move.

Platform Stacks (edge, monitoring, ops, doco-cd) are the only Stacks grouped by role rather than by app, and the only ones that may hold more than one app. arr was grouped by workflow when the topical Stacks were split; it is split into one Stack per app (sonarr, radarr, sabnzbd, qbittorrent, autobrr), so each Service ships on its own release schedule and Deploys alone.
